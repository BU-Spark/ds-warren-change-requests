# Workspace sign-in

The default login uses a shared access code, initially **1234**. No email,
invitation, or password setup is needed. Set the app variable
`WARREN_ACCESS_CODE` to a new case-sensitive code of 4–128 letters/numbers and
redeploy to change it. This also revokes existing code sessions. Treat `1234`
as temporary; use a longer code before sharing client access.

Code sessions last one hour, use HttpOnly cookies (Secure on HTTPS), store only
session-token hashes in the database, and are revoked on sign-out. Login
attempts are limited. The code is never sent to the browser except when entered
by the user. Every code holder shares reviewer permissions, including document
deletion; individual account identity and Manage accounts are unavailable.

`WARREN_AUTH_MODE=code` is the default. Keep `WARREN_PUBLIC_URL`, database and
volume settings as described in [Railway deployment](RAILWAY.md).

## Optional invite-only accounts

The following workflow is available with `WARREN_AUTH_MODE=accounts`.
Existing accounts remain stored when changing modes. To enable these flows,
set this variable for both the server and operator commands.

The reviewer manages its own accounts. No Supabase, email sender, public sign-up,
or automatic email verification is used. Email addresses are login identifiers;
accepting an invitation does **not** independently verify email ownership. An
app admin must confirm the recipient's identity and share the link privately.
All approved reviewers share the same document workspace.

## Local setup and the first admin

Use the same Python environment and variables for the server and management
commands. With no `DATABASE_URL`, local development uses
`data/reviewer/reviewer.sqlite3`; PostgreSQL is selected when `DATABASE_URL` is
set. Schema tables are created automatically without inserting any default user.

```bash
export WARREN_PUBLIC_URL='http://127.0.0.1:8000'
export WARREN_AUTH_MODE=accounts
python -m reviewer.manage_accounts invite admin@example.com --admin
python -m reviewer
```

Replace the sample address with the intended admin's address. Open the private
link printed by the management command, click Continue, choose a password of
12–128 characters, and sign in. **Manage accounts** appears for app admins only.
There is no default password and passwords must never be inserted as plaintext
database rows. Argon2id hashes are generated by the application.

For Railway, run the management command **inside the deployed app container**
with its existing environment (for example through `railway ssh`, if authorized).
The command prints a secret link intentionally; don't copy its output into
public logs, screenshots, tickets, or Git. Someone with deployment/operator
access must bootstrap the first app admin. App-admin permissions and Railway
project permissions are separate.

## Inviting and managing reviewers

1. Sign in as an app admin and open **Manage accounts**.
2. Enter the reviewer's email and create an invitation link.
3. Share it privately after confirming identity. It expires in 24 hours.
4. The reviewer accepts it, sets a password, and signs in. No email is sent.

Admins can replace a pending invitation, create a reset link for an active
account (15-minute expiry), and disable a reviewer. A reset link lets the
recipient choose a new password; it never reveals the old password. Account
setup must be completed within 10 minutes after opening an access link.
Links and setup grants are single-use. Completing password setup/reset revokes
all existing sessions and outstanding access links for that account.

**Disable access** immediately revokes sessions and outstanding links. The web
interface does not disable app admins; use operator commands for that. Disabled
accounts cannot sign in or receive recovery links. Reactivating a disabled
account is not offered by this version; an operator should review the account
before any database change, rather than creating a duplicate identity.

Operators can also run these commands in the same app environment:

```bash
python -m reviewer.manage_accounts invite reviewer@example.com
python -m reviewer.manage_accounts reset reviewer@example.com
python -m reviewer.manage_accounts promote reviewer@example.com
python -m reviewer.manage_accounts disable reviewer@example.com
```

Only operators can promote app admins. Public request fields cannot grant an
admin role. Management responses never include password hashes or stored token
hashes. Raw links are shown only when generated, and are not retained by the UI
after closing the dialog.

## Authentication controls

- No configured origin means startup fails. A disposable local synthetic demo
  may explicitly use `WARREN_ALLOW_UNAUTHENTICATED=1` with no
  `WARREN_PUBLIC_URL`; this disables all access protection. Railway rejects this
  bypass. Remove obsolete `WARREN_SUPABASE_*` and `WARREN_ALLOWED_EMAILS` settings.
- Hosted deployments require HTTPS, PostgreSQL, and a configured persistent
  data path. Origin checks protect writes, including login and account actions.
- One-hour sessions use random opaque tokens. Only token hashes are stored;
  HttpOnly, SameSite cookies carry the browser secret and use Secure on HTTPS.
  Logout invalidates the token on the server, including copied cookies.
- Password changes and disabled accounts invalidate existing access. Tokens
  survive app restarts only while valid in the database.
- Authentication submissions have a shared limit of 30 per minute per app
  process. Run one replica and one worker; this is not a distributed limiter.
- Local HTTP is allowed only with a loopback origin. Local OS users with access
  to the data files remain outside the protection supplied by browser login.

See [Railway deployment](RAILWAY.md) for the database, volume, and domain setup.
